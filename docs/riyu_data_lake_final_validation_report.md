対象は2020年の天鳳四麻半荘 GO 169。2026年11月27日、Mac M4・24 GB。実装した教師仕様は `local-actions-v1`。RustがParquetへ直接出力し、Pythonは独立検証と学習時の読み込みを担う。

## 2. 副露教師と保存仕様

`targets/local_actions` は疎な表で、`decision_id: fixed_binary(16)` と `action_set_hash: fixed_binary(32)` で実局面の候補集合を参照する。打牌・PASS以外の候補がある局面だけに行を持つ。`before` は局面に1回、`candidates` は親候補ごとに1件。親を `action_index: u8` で参照する。チー・ポンの子は `id: fixed_binary(8)`、`semantic: binary` と `successor_set_hash: fixed_binary(32)` を持つ。子の識別子は `(decision_id, 親ActionId, 子ActionId)`。同じ打牌が別の副露から発生しても、その前提状態を取り違えない。

親候補は赤牌の消費差を区別する。条件付きで副露イベントを適用し、元の合法手生成と天鳳の食い替え制約を適用する。打牌の子には `after_discard`、河から計算した `genbutsu_mask: u8`、他家3席の `ron` が付く。現物のビットは絶対席。子に実際の選択・以後の点数・順位を付ける列はない。

| 列 | 保存値と扱い |
|---|---|
| `before` / `after` / `after_discard` | 最小・通常・七対子・国士の向聴数、構造待ちと受け入れの34ビットマスク、理論・可視残枚数、門前、副露数、手牌・ツモ牌の意味コード、赤と公開ドラの保有数 |
| `transition_status` | 副露の優先権成立、搶槓なしの槓成立、リーチ宣言打牌の受理前、和了成立、途中流局宣言を示す |
| `ron` / `kan_robbery` | 相手席、ロン合法性、合法性の状態、単独ロン条件の失点、裏・責任払いを除いた条件計算、打点の状態 |
| `visible_win_score` | 公開済みの表ドラと自席の手牌で和了を評価した役・符・飜・支払内訳。既存の得点評価JSONを格納し、未確定の得点は状態列で明示する |

Parquetの全フィールド・型・nullable項目は[共有スキーマ](../schemas/riyu-data-lake-pilot-v1.json)。Rust直結・IPC、および[旧JSONL梱包経路](../tools/pack_riyu_lake.py)で列定義を共有する。

同じ2対局を3経路で生成し、17表のArrow型、属性、全行の値が一致した。

## 3. 副露後の打牌例

[合成回帰テスト](../engine/data-lake/src/local.rs)の一例。自席は1、上家は0。赤5萬と通常5萬の両方を持ち、上家の4萬に対して赤5萬と6萬でチーする親は `[1, 2, 6, 3, 9, 10]`。赤5萬を使った親の打牌は、3萬、通常5萬、8萬、1筒、3筒、3索、東、西の8候補。4萬と7萬は食い替えで除く。同じ牌の物理コピーは1候補にまとまる。通常5萬でチーする別の親では、手牌に残る5萬が赤5萬に変わる。

通常5萬を切る子は `[1, 0, 8, 0]`。この子の `after_discard` の手牌は10枚で、副露1組を加えた構造は13枚。親の直後は構造14枚なので、受け入れと待ちは子の打牌後に確定する。実牌譜から検査した候補数と一致判定は集計で示す。

## 4. PASSと観測不能な応答

| `targets/policy.resolution` | 方策での扱い |
|---|---|
| `selected` | 選択を元イベントで一意に対応付け、合法集合も確定 |
| `confirmed_pass` | 次ツモによる終端と確定した合法集合からPASSと判定 |
| `priority_censored` | 他者の優先行動や一部の終端で個人の応答が観測不能。選択はNULL |
| `incomplete_legal_set` | フリテン不明による合法集合の不確定。実選択が特定できる場合にも方策マスクは落とす |

PASS以外の合法手がない確定窓は意思決定表から省く。年度検証では公開イベントから打牌・暗槓・加槓の応答窓を数え、保存した応答席数との差を集計する。副露率にはチー・ポン・大明槓のいずれかが合法だった窓のうち、実副露または確定PASSの窓を使う。ロンを選んだ窓と選択不明の窓は別に報告する。監査JSONは合法機会、当該行動の選択、確定PASS、不明を副露種別・全員通算ツモ巡の24刻み・自席向聴数・受理リーチ有無別に返す。

## 5. リーチと槓

リーチ宣言牌と同一の牌・手出し／ツモ切り区分を持つダマ打牌を `dama_index` で結ぶ。宣言前の自席手牌・点数と供託、宣言打牌後の手牌・待ち・可視残枚数、受理した場合の1,000点を記録する。即時ロンと条件付き失点は共通の根の守備列を参照する。実際の受理は `targets/policy.riichi_accepted` と、対応する元 `REACH step=2` の順序番号で管理する。宣言牌でロンされ受理されなかった事例はfalse。未選択候補には受理の実績がない。

槓は大明槓・暗槓・加槓を別のActionIdとする。槓成立後・嶺上ツモ前の手牌構成、副露数、向聴数、待ち、一発消滅を保持する。暗槓のドラは嶺上前に公開し、加槓・大明槓は遅延公開する対象ルールとした。暗槓・加槓の搶槓は相手別に計算する。GO 169/225では国士の暗槓搶槓を認める切替が無効。大明槓は元の捨て牌に対する優先行動であり、別の搶槓窓は生じない。4つ目の槓かつ複数人での槓は四槓散了の発生条件として保持する。嶺上牌をツモした場合の残枚数は計算できる。嶺上牌、次打牌、公開されるドラの種類、途中流局が確定する後続はその時点で未観測。

受理リーチ後の暗槓はツモ牌の牌種と槓後の待ちの一致を既存ルールで検査する。槓前の構造13枚の待ちが必要な場合は `before.concealed` から復元できる。[暗槓と立直の合法手判定](../engine/core/src/legal.rs)・[天鳳公式の四麻ルール](https://tenhou.net/man/#rule)

## 6. 攻撃教師の計算と検証

既存のRustの向聴・受け入れ計算を共有し、チー・ポン直後と子の打牌後を分けた。七対子・国士は固定面子がある場合にNULL。待ちマスクは構造13枚かつ聴牌時だけ値を持つ。理論残枚数は改善牌種ごとに4から暗手中の同種枚数を引く既存定義。可視残枚数は自席牌、全員の河、副露、公開ドラ、宣言された槓を差し引く。鳴かれた河の牌は副露として一度だけ数える。実際の山での残枚数には拡張していない。

門前限定役の可否を決める条件は `closed` で追跡する。リーチ、門前清自摸和、平和、一盃口などの門前条件が副露で変わる。役牌・断么九・混一色・清一色・対々和・三色同順・一気通貫・チャンタ・純チャンなどは、現時点の手牌構成や固定面子を参照できる。個々の役が将来何巡で成立するかは選択、他家の行動、ツモに依存する。実和了の役は元和了イベントで保持し、現時点で合法な和了の役は得点評価で計算する。

独立検査はPython Mahjongの向聴数・形の改善、自席と公開牌の別集計、子の手牌差分を使う。[局所教師監査](../tools/audit_riyu_local_actions.py)

暗手の同種4枚を刻子と孤立牌に分解できる例では、既存の構造向聴が0でも、5枚目が必要なため受け入れマスクが0になり得る。Python Mahjongはこの形に補正を適用する。監査では独立の面子分解でも構造向聴を照合し、補正の有無による差を別に集計する。聴牌の学習条件に実在可能な待ちが必要な場合は、向聴0と受け入れマスクを併用する。[形の回帰テスト](../tests/python/test_lake_audit.py)

## 7. 守備教師の計算と検証

根の打牌・リーチ宣言牌、副露の子打牌、暗槓・加槓の搶槓を相手別に検査する。鳴きが成立した世界では一発を消し、元がリーチ宣言牌なら宣言の受理を適用する。先行応答を観測できなかったことでロン可否が変わり得る場合はNULL。裏ドラ・責任払い・未公開槓ドラ・フリテン不明が残る場合は確定点をNULLにする。条件付き打点は公開済み表ドラ、裏ドラなし、責任払いなしの単独ロンとして別に記録する。複数ロン時の実精算は勝者優先順位・供託・本場を含む実結果を参照する。NULLを安全や0点として入力しない。

局面再現と教師を別に検査した。特殊牌譜52対局と既知の回帰牌譜6対局はすべて再現。特殊牌譜では三家和6、四槓散了6、責任払い6和了、搶槓6和了、複数ロン7局、リーチ宣言牌のロン16件、精算452件を独立照合した。遅延槓ドラの既知3件は確定打点の代わりに未公開の状態となった。チー・ポン後の一時フリテン、非隣接の鳴きに伴う不明応答の回帰標本も通過した。最終嶺上ツモに海底役を重ねないことをRustテストで確認した。

独立監査は、元ログからの実精算と条件付き失点、公開状態と他家の手牌教師を与えた標本上の次の打牌のロン・表ドラ得点を検査した。選択・未選択の根候補と、副露後・槓の局所候補を対象にする。[実和了・Belief監査](../tools/validate_riyu_lake.py)

## 8. Beliefと価値の正確性

Belief Liteは向聴数、待ち、フリテン、手牌枚数、次の行動を持つ。Fullは34種の暗手枚数、赤マスク、本人ツモで構成する。別実装で観測イベントから手牌を再構成し、枚数、赤、ツモ、待ちと向聴数を照合する。次の実選択、局精算、半荘点数と順位は実績教師。段位戦報酬はルール・卓・段位・時期に対応した報酬表の別定義が必要。

## 9. 牌山

前回の128半荘で一致した配牌、通常ツモ、嶺上、ドラ、裏ドラまでを独立に確認済みの境界とする。今回は復元山を新規教師やモデル入力に使用していない。実際の残り山・裏ドラ付きの条件評価は、牌山利用が許された非公開の検証用として後から追加できる。実山を使う反実仮想と、観測から推定した山を使う探索は別々の実験条件となる。

## 10. 情報漏洩の検証

Rustの観測投影は、自席以外の非公開ツモを欠損にし、意味牌へ変換した自席手牌、公開情報と自席の行動候補を作る。物理コピー・元イベントは `restricted/`、SHUFFLEや牌山は入力経路の外、隠れた手牌・未公開の局所教師・以後の実成績は `targets/`。候補生成に使う暗手は自席分だけ。物理台帳は天鳳の公開カン数などを参照する制約と行動の物理実行対応に使い、モデル向けActionIdは牌種、赤、手出し／ツモ切り、鳴き元の相対席などから計算する。

テストでは、同じ時点の他家の手牌と物理コピーを変えても観測と合法手ハッシュが同一だった。別のPythonテストは非公開手牌・選択・最終点数・物理IDを変更したファイルで、ローダーとEncoder経由の入力テンソルが等しいことを確認した。履歴は指定席・局の観測時点までで切り、後続イベントがあるfixtureで打ち切りを確認した。[Rust再現テスト](../engine/data-lake/src/replay.rs)・[パイプラインテスト](../tests/python/test_lake_training.py)

## 11. 学習用ローダー

[`LakeTrainingLoader`](../python/mahjong_ai/data/lake_training.py)は半荘単位で分割し、1シャードずつ開く。入力は型を固定しない観測、意味ActionId、アクションコード、局面ごとの平坦化オフセット、任意の観測履歴。点棒、局、親、本場、供託、河、手出し、ツモ切り、鳴き、リーチ、ドラ、残枚数、全員通算ツモ巡は観測に含まれる。席別の巡は河・イベント列から導出できる。

`batches(targets={"policy": ["choice", "trainable"], "belief_lite": ["opponents"]}, history=True)` で必要な最上位Parquet列を選べる。教師を省略した場合は教師ファイルを開かない。方策、攻撃、守備、Belief Lite/Full、局、半荘、和了、局所枝を選択できる。教師は `LakeBatch.targets` に返り、`LakeBatch.encode(encoder)` は `ObservationBatch` だけを渡す。局所枝には親のインデックスと子ごとのリストが残る。マスク付き方策学習では `trainable` を使う。時系列Encoderへは当該局面の履歴を入力する。

## 12. 保存方式CとD

同じ16対局の学習側9,559意思決定について、スナップショットと候補コードの集約ハッシュが4経路で一致した。計測はParquet読込・展開・出力チェックを含み、モデルの転送と学習を含まない。

| 学習入力の供給方式 | 読込・展開時間 | 備考 |
|---|---:|---|
| Cから局頭を再生 | 1.62秒 | 1シャード内で自席・局ごとにまとめて順次適用 |
| Cのチェックポイントを利用 | 4.23秒 | 最初の要求時点の直前から1回再生。小標本の全順次走査では追加入力がある |
| Cから派生スナップショットを作成 | 1.27秒 | 初回の作成は1.80秒、全分割分922,063 B |
| Dを直接出力して読み込み | 1.25秒 | 同じ16対局の全Parquet容量6.87 MB。Cは5.92 MB |
| Cを診断用Tensorへ固定 | 0.008秒 | 生成1.65秒、4,167,852 B。メモリマップからの配列走査だけの測定 |

Cを正本とし、まとまった順次走査は局頭再生、疎な復元はチェックポイント、繰り返す学習の固定入力には派生スナップショットを選ぶ。Dを使う場合は初回から展開が必要な実験に絞る。TensorキャッシュはEncoder・設定・分割・元リリースが固定されたときの派生物。109次元は性能測定にのみ使用した。[比較ツール](../tools/bench_riyu_training_view.py)

## 13. 固定1万対局の加工結果

同じ年間分散標本を使用。抽出計画のSHA-256は `c2d1207dbb1586867a0f2a1172515796a85ee6149a575433dfa96dfc11341c46`。12か月の各833–834対局からなり、別枠の特殊牌譜は結果に加えていない。

1,000対局の前段検査は全件再現し、10,580局・649,979意思決定、チー・ポン後の合法打牌1,269,308件。実精算8,866和了、確定単独ロン失点3,291件、Belief 19,401手、独立局所攻撃378件、独立守備1,944セルで不一致0。監査の間隔と標本数を明記し、全候補の列結合・重複・食い替え検査と標本の再計算を区別する。

範囲4,544–4,559で品質ゲートが停止した。1半荘の元XMLでは同一席が通常ツモ、打牌、白の暗槓の順で記録され、打牌と暗槓の間に新たなツモがない。どちらも適用すると槓成立直後の構造手牌は12枚となる。独立の牌山検証で同半荘の通常ツモ501回、嶺上ツモ1回、配牌44手が一致した。元イベントに修正を加える証拠がないため半荘全体を `replay_rejected` とし、教師を生成せず制限付きの診断に保持した。停止前と同一のバイナリ・設定・標本で再開し、確定済みシャードのハッシュと契約を再確認した。[天鳳公式の四麻ルール・牌譜仕様](https://tenhou.net/man/)

**10,000対局を処理し、9,999対局・106,211局・6,522,005意思決定を再現。1対局を隔離。** Parquet 625シャードすべてのファイルSHA-256、行数、教師と候補の整合、半荘分割を照合した。合法手の意味的重複、選択根拠と候補の不一致、食い替え違反、分割間の半荘重複は0件。学習8,022、検証1,032、最終評価945半荘。

## 16. 加工時間・保存容量

1万対局のParquetは **3.698 GB**。局所枝だけで400.28 MB（10.8%）。停止前と再開後の計測合計は **30.7分** で、再開時の確認とアーカイブの再読込を含む。両工程のピークRSSの最大は **2.97 GB**。シャード内の読込・再現・書込フェーズの合計は20.1分。元XMLの診断作業とPython監査は加工時間の計測外。

## 18. 未解決事項

- 観測不能な応答、優先順位で失われた個人選択、各未選択候補からの将来結果は元ログでは同定できない。
- 局所的な可視残枚数を実際の山の残り枚数として扱う用途には追加の牌山検証が必要。
- 複数ロンや責任払いを含む未選択候補の全体純失点、一部の隠れたフリテン、未公開の槓ドラ・裏ドラは条件付きのまま。裏ドラを推定して確定点に置換する処理はない。

## 19. 全量加工の判断

GO 169の正常な牌譜について、試験リリースを学習データ供給経路の基準にできる。1万対局の完全再現は元XMLの順序矛盾1件により未達。隔離した半荘に教師を付けず、原因不明の拒否は品質ゲートに残す。

計測したローカル空きは約52 GiBで、方式Cの全量見積もりを下回る。全量加工は出力と再開・隔離用に十分な保存先を確保してから判断する。今回は全量加工、モデル学習、外部への牌譜転送は行っていない。

## 20. 次のモデル設計に必要な情報

行動横断の比較には、観測から半荘報酬を推定するモデルと、合法手の可変軸、教師の欠損マスクが必要。出力は局所的な向聴数・即時失点・他家推定を別タスクで学べる。最終報酬を比較するには段位戦の報酬表、参照する対局条件、時系列評価とプレイヤー偏りの設計を確定する。未選択の枝の将来は観測データ単独で同定できないため、将来の評価では明示的な他家方策とサンプリング方針を伴う。
