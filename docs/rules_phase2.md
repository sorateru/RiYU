# Phase 2 ルール対応表

確認基準は一般的な四人リーチ麻雀とする。ルール差は `RuleConfig` に保持し、暗黙のグローバル設定を作らない。

## 完了済み

### 牌姿計算

- 通常形、七対子、国士無双の最小シャンテン
- 副露・暗槓を固定面子として扱うシャンテン
- 有効牌の種類と、公開済み／自分の既知牌を差し引いた残枚数
- 赤牌と通常5を物理的に別の打牌候補として保持
- 全打牌候補を「シャンテン昇順、受け入れ降順」で並べる厳密牌効率
- 標準形の複数解釈、七対子、国士の和了形分解

牌効率順位は厳密計算であり、局収支・放銃・順位条件を含むAI推奨ではない。学習済みモデルがない場合、解析JSONのモデル値は `unavailable` のまま返す。

### 役・符・点数

- リーチ、ダブルリーチ、一発、門前ツモ
- タンヤオ、平和、一盃口、二盃口
- 役牌、海底、河底、嶺上開花、搶槓
- 七対子、対々和、三暗刻、三槓子
- 三色同順、三色同刻、一気通貫
- 混全帯幺九、純全帯幺九、混老頭、小三元
- 混一色、清一色
- 天和、地和、国士無双、四暗刻、大三元
- 小四喜、大四喜、字一色、清老頭、緑一色、九蓮宝燈、四槓子
- 一般的なダブル役満設定
- 赤、表ドラ、裏ドラ（ドラだけでは和了不可）
- 待ち形、面子、雀頭、門前ロン、ツモによる符
- 満貫〜役満、切り上げ満貫、数え役満／三倍満上限
- ロン・親ツモ・子ツモ、本場、供託

### 合法手と局進行

- 手牌の物理牌を保持した打牌、ツモ切り
- 門前、点数、残り牌、テンパイを確認したリーチ候補
- 上家限定チー、ポン、大明槓、暗槓、加槓
- 役のあるロン／ツモ
- 捨て牌フリテン、一時フリテン、リーチ後見逃し
- リーチ後ツモ切り制約と待ち不変の暗槓判定
- ノーテン罰符、連荘、本場、供託、親移動
- 東風／半荘、アガリ止め、テンパイ止め、飛び、延長戦
- ダブルリーチと一発のイベント自動追跡
- 暗槓・加槓の搶槓応答窓と、成立時だけ副露を確定するpending kan
- 九種九牌の合法手、四風連打・四家立直・四槓散了（一人四槓を除外）の検出
- 複数ロンの本場・供託配分と、責任払いを含む点数移動の純粋計算
- 完全情報から4人別の観測状態へ秘密牌を隠して投影するSimulator

## 未完了として扱う項目

- 大三元・大四喜の責任者を副露履歴から自動認定する処理（点数移動関数は実装済み）
- 流し満貫
- 頭ハネ、供託分割など複数ロンのローカル配分差（既定は上家側の最初の和了者が供託取得）
- 連風牌雀頭を2符とするルール差以外のローカル符規則
- 人和など一般ルール外のローカル役
- 順位決定時の同点起家順、オカ、ウマ

これらは入力で成立済みと仮定して補完せず、対応コードとfixtureが追加されるまで厳密計算として表示しない。

## クロスチェック

`tools/crosscheck_shanten.py` はMITライセンスの `MahjongRepository/mahjong==1.4.0` と比較する。固定seedで固定副露数0〜4、13/14枚相当の合計5000牌姿を照合し、現在は全件一致している。

```bash
python tools/crosscheck_shanten.py
```

採点は手作業の代表fixtureだけで完了扱いにしない。共通イベントログで和了結果を正規化できるが、配布条件を確認済みの大規模fixtureによる全役クロスチェックは継続課題である。
